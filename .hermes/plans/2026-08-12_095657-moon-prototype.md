# moon Migration Prototype Implementation Plan

> **For Hermes:** Execute this as a throwaway prototype branch, one
> evidence-producing slice at a time.

**Goal:** Demonstrate how moon 2.4.6 can orchestrate the existing
pnpm/Node/Maven project without removing Turbo, changing application code, or
changing production workflows.

**Architecture:** Keep pnpm and every project command as the execution seam. Add
moon as a parallel scheduler with explicit project discovery and task
inheritance limited to projects that actually provide each script. Preserve
Turbo, releases, Dockerfiles, and remote-cache wiring until parity is
established.

**Tech Stack:** moon 2.4.6, pnpm 10.28.0, Node.js, Maven, Turborepo.

---

## Change contract

- **Writable target:** `prototype/moon-migration` branch in this repository.
- **In scope:** moon configuration, root opt-in prototype commands, ignored
  cache paths, a concise prototype verdict, and verification evidence.
- **Preserve:** pnpm workspace/lockfile, package scripts, current Turbo
  commands/configuration, application behavior, Changesets, Dockerfiles,
  release/deploy workflows, credential indirection, and unrelated files.
- **Allowed side effects:** create/switch a local branch; add/edit files in the
  checkout; run local moon/Turbo/pnpm/Maven verification.
- **Forbidden side effects:** push, merge, commit, publish, deploy, modify CI
  secrets, configure remote caching, run Supabase-backed E2E, or remove Turbo.
- **Acceptance:** moon sees exactly all 10 projects; applicable tasks resolve
  without inheriting nonexistent scripts; representative task graphs match
  declared workspace dependencies; lint/typecheck/test/build run through moon; a
  second cacheable run demonstrates cache reuse; Turbo verification remains
  available and passes; complete diff is reviewed against this plan.

## Verification seams

The public interfaces under test are:

1. **Project graph:** `moon project-graph`/`moon projects` represents the ten
   pnpm workspaces and their internal dependencies.
2. **Task selection:** `moon run :<task>` selects only projects that provide
   that task.
3. **Command behavior:** moon delegates to the existing package scripts, so
   observed success/failure remains comparable to direct pnpm/Turbo execution.
4. **Cache behavior:** a repeated deterministic task reports cached work and
   restores declared outputs where applicable.
5. **Coexistence:** existing `pnpm verify` and Turbo configuration remain
   intact.

## Task 1: Create an isolated prototype branch

**Objective:** Establish a reversible branch and record the clean baseline.

**Steps:**

1. Verify `main` is clean and aligned with `origin/main`.
2. Create `prototype/moon-migration` from current `main`.
3. Record the branch and baseline SHA in the prototype verdict.

**Verification:** `git status --short --branch` reports the prototype branch
with no pre-existing changes.

## Task 2: Generate the minimal moon v2 workspace

**Objective:** Add moon without cutting over any existing interface.

**Files:**

- Create: `.moon/workspace.yml`
- Create: `.moon/toolchains.yml`
- Create: `.prototools` only if exact versions can be derived without
  contradicting the repository.
- Modify: `.gitignore`
- Modify: `.dockerignore`

**Steps:**

1. Pin moon to 2.4.6 using its supported workspace constraint/configuration.
2. Configure project globs for both `apps/*` and `packages/*`.
3. Set `main` as the VCS default branch.
4. Configure JavaScript/Node/pnpm integration while continuing to use the
   installed toolchain where pinning would introduce an arbitrary decision.
5. Ignore `.moon/cache` locally and in Docker contexts.

**Verification:** moon loads the workspace and reports exactly 10 projects.

## Task 3: Add explicit, safe task inheritance

**Objective:** Reproduce Turbo's task surface without applying nonexistent
scripts to projects.

**Files:**

- Create: `.moon/tasks/node.yml` or narrowly split files under `.moon/tasks/`
- Create/modify: project `moon.yml` files only where metadata or overrides are
  required.

**Steps:**

1. Use moon's Node task inference if it safely exposes package scripts.
2. Otherwise define tasks conditionally by required files/scripts or
   include/exclude them per project.
3. Translate build dependency ordering from `^build` to `^:build`.
4. Preserve applicable build inputs, environment inputs, uncached clean/dev
   behavior, persistent development mode, and outputs each command actually
   creates. Do not carry broad Turbo output declarations onto commands that do
   not emit those artifacts.
5. Keep Java commands delegated through the existing
   `apps/java-api/package.json` scripts for this prototype.

**Verification:** dry-run/query every task and prove no target invokes an absent
package script.

## Task 4: Add opt-in root commands

**Objective:** Make the prototype trivial to try without changing existing
commands.

**Files:**

- Modify: `package.json`
- Modify: `pnpm-lock.yaml` only if a local moon CLI dependency is needed.

**Steps:**

1. Add namespaced scripts such as `moon:build`, `moon:lint`, `moon:test`,
   `moon:check-types`, and `moon:verify`.
2. Leave `build`, `lint`, `test`, `check-types`, `verify`, `release`, and `dev`
   unchanged.

**Verification:** existing scripts still resolve to Turbo; namespaced scripts
resolve to moon.

## Task 5: Prove representative parity and caching

**Objective:** Collect runtime evidence rather than relying on config
inspection.

**Steps:**

1. Compare Turbo and moon dry-run task/project selections.
2. Run moon lint and type checking.
3. Run moon tests.
4. Run moon builds, including the Maven-backed Java project.
5. Repeat a deterministic cacheable target and inspect moon's cache result.
6. Run the repository's established Turbo-backed `pnpm verify` as the final
   regression gate. If a baseline or host prerequisite blocks it, reproduce the
   failure through both runners and record the exact boundary instead of
   claiming a pass.

**Verification:** Record exact command outcomes and any differences in
`.scratch/moon-migration/prototype-verdict.md`, with a tracked summary under
`docs/prototypes/` for branch review.

## Task 6: Review the prototype diff

**Objective:** Ensure the branch demonstrates coexistence rather than silently
beginning a cutover.

**Steps:**

1. Inspect every changed file relative to `main`.
2. Run Standards and Spec review against this plan.
3. Fix high-confidence findings.
4. Leave the branch uncommitted and unpushed for Joe to inspect and author the
   commit if desired.

**Verification:** Every changed file is explained; no Dockerfile, workflow,
Turbo config, application source, dependency version, or secret surface changed
outside the contract.

## Deferred from this prototype

- Replacing `turbo prune` in four Dockerfiles.
- Migrating release/deploy affected semantics.
- Selecting/provisioning moon remote cache.
- Removing Turbo, `eslint-plugin-turbo`, or `@turbo/gen`.
- Changing exact Node/Java version policy.
- Running local Supabase E2E against any environment.
